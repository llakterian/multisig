\section{Executive Summary}

\subsection{Key Innovation}
This platform represents a revolutionary approach to land acquisition, combining blockchain technology with traditional legal processes. By integrating Ethereum smart contracts with real-world legal milestones, we create a trustless, transparent, and secure environment for property transactions.

\subsection{Core Components}
\begin{itemize}
\item \textbf{MultiSigWallet:} A secure multi-signature wallet requiring M-of-N confirmations
\item \textbf{NotaryMediatedEscrow:} State machine managing the entire transaction lifecycle
\item \textbf{EscrowFactory:} Factory contract for deploying new escrow instances
\end{itemize}

\section{The 4-Phase Workflow}

\subsection{Phase 1: Intake \& Discovery}
The process begins when a client submits their requirements:
\begin{enumerate}
\item Client creates an intake with budget, desired property size, and purpose
\item Notary uploads digital gallery of available properties
\item Client selects a property from the discovery phase
\item Client funds the escrow with due diligence fee
\end{enumerate}

Key Features:
\begin{itemize}
\item Budget validation against minimum due diligence fee
\item Digital gallery for property exploration
\item Property selection triggers plot locking
\end{itemize}

\subsection{Phase 2: Due Diligence ``Safety Gate''}
This critical phase involves comprehensive verification:

\begin{enumerate}
\item Notary conducts registry search
\item Notary performs site visit
\item Notary uploads due diligence report
\item Client verifies and releases due diligence milestone payment
\end{enumerate}

Security Features:
\begin{itemize}
\item Title search verification
\item Site inspection reports
\item Document hashing for immutability
\item Multi-party verification requirements
\end{itemize}

\subsection{Phase 3: Execution \& The Fiat Bridge}
Once due diligence passes, execution begins:

\begin{enumerate}
\item Both parties sign the sale agreement on-platform
\item Notary notarizes the signed document
\item Client deposits full remaining amount
\item Fiat bridge converts crypto to KES (K Kenyan Shilling)
\item Funds disbursed to seller (minus facilitation fee)
\end{enumerate}

Fiat Bridge Features:
\begin{itemize}
\item Notary executes fiat bridge with exchange rate
\item Converts cryptocurrency to local currency
\item Records KES amount and exchange rate on-chain
\item Disbursement to seller and facilitation fee to treasury
\end{itemize}

\subsection{Phase 4: Transfer Registry \& Finalization}
The final phase handles title transfer:

\begin{enumerate}
\item Notary uploads lodgement receipt
\item Client confirms final transfer
\item Notary uploads original title documents
\item Multi-sig owners confirm final release
\item Title issued with courier tracking
\end{enumerate}

Completion Features:
\begin{itemize}
\item Original title document verification
\item Land Registry confirmation
\item Courier tracking integration
\item Facilitation fee release to treasury
\end{itemize}

\section{Smart Contract Architecture}

\subsection{MultiSigWallet.sol}
The MultiSigWallet provides secure fund management:

\begin{lstlisting}[language=Solidity]
contract MultiSigWallet {
    address[] public owners;
    mapping(address => bool) public isOwner;
    uint public numConfirmationsRequired;
    
    struct Transaction {
        address to;
        uint value;
        bytes data;
        bool executed;
        uint numConfirmations;
    }
}
\end{lstlisting}

Key Features:
\begin{itemize}
\item M-of-N signature requirement
\item Transaction submission by owners
\item Confirmation and execution flow
\item Non-reentrant protection
\end{itemize}

\subsection{NotaryMediatedEscrow.sol}
The core escrow state machine:

\begin{lstlisting}[language=Solidity]
enum EscrowState { 
    Created, Intake, Discovery, PlotSelected,
    Funded, DueDiligencePending, DueDiligenceComplete,
    ExecutionPending, ExecutionComplete, 
    TransferRegistry, Completed, Cancelled 
}
\end{lstlisting}

State Transitions:
\begin{enumerate}
\item Intake $\rightarrow$ Discovery (gallery upload)
\item Discovery $\rightarrow$ PlotSelected (plot selection)
\item PlotSelected $\rightarrow$ DueDiligencePending (funding)
\item DueDiligencePending $\rightarrow$ DueDiligenceComplete (DD completion)
\item DueDiligenceComplete $\rightarrow$ ExecutionPending (proceed)
\item ExecutionPending $\rightarrow$ ExecutionComplete (fiat bridge)
\item ExecutionComplete $\rightarrow$ TransferRegistry (lodgement)
\item TransferRegistry $\rightarrow$ Completed (final transfer)
\end{enumerate}

\subsection{EscrowFactory.sol}
Factory pattern for creating escrows:

\begin{lstlisting}[language=Solidity]
function createEscrow(
    address _seller,
    address _notary,
    uint _totalAmount
) public returns (address escrowContract)
\end{lstlisting}

Features:
\begin{itemize}
\item Default notary and owners configuration
\item Batch escrow creation
\item Treasury and fee configuration
\item Pending action timelock mechanism
\end{itemize}

\section{Security Features}

\subsection{Multi-Signature Verification}
\begin{itemize}
\item All fund releases require multi-sig approval
\item Configurable M-of-N threshold
\item Separate execution from confirmation
\end{itemize}

\subsection{Document Hashing \& Verification}
\begin{itemize}
\item All documents hashed using keccak256
\item Hashes stored in contract state
\item Client can verify document authenticity
\end{itemize}

\subsection{Access Control}
Role-based permissions:
\begin{itemize}
\item Client: Create intake, sign documents, verify
\item Notary: Upload reports, execute fiat bridge, complete transfer
\item Treasury: Upload gallery, receive facilitation fees
\item Owners: Confirm and execute transactions
\end{itemize}

\subsection{State Machine Protection}
\begin{itemize}
\item Strict state transition validation
\item No skipping phases
\item Reentrancy guards on critical functions
\end{itemize}
