# Security Policy

## Supported Versions

Only the latest released version of SafeShamba is supported with security fixes.

## Reporting a Vulnerability

If you discover a security vulnerability, please report it responsibly:

1. **Email:** security@safeshamba.com
2. **Do NOT** open a public GitHub issue
3. Include as much detail as possible:
   - Description of the issue
   - Steps to reproduce
   - Impact assessment
   - Suggested fix (if any)

## Response Time

- **Critical:** 24 hours
- **High:** 3 days
- **Medium:** 7 days
- **Low:** 14 days

## Known Issues

See [SECURITY_AUDIT_SUMMARY.md](SECURITY_AUDIT_SUMMARY.md) for the current security posture.

## Security Best Practices

### For Deployers
- Always run security audits before mainnet deployment
- Use hardware wallets for treasury keys
- Configure proper multisig thresholds
- Monitor contract activity

### For Users
- Verify contract addresses before interacting
- Use official frontend only
- Never share private keys
- Report suspicious activity immediately

## Disclosure Policy

We coordinate with security researchers to ensure vulnerabilities are properly addressed before public disclosure.
